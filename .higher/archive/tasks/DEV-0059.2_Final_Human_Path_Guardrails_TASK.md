# 2. P0 · Review 周期必须使用用户设置的 cadence，并禁止重复 Review

## 当前缺口

`PlanningTruthSummary.startReview()` 当前固定：

```text
period_start = today - 14 days
```

因此：

- 用户设置 7 / 30 天仍然审 14 天；
- `BETWEEN` 是包含端点，`today-14 .. today` 实际覆盖 15 个日历日；
- running review 时按钮仍可再次创建新的 review。

## 修复

把周期计算放 Backend/Repository，禁止由 UI 自己硬编码。

新增/演进现有命令（不要第二套 Review 系统）：

```text
prepare_current_planning_review(profile_id, trigger_type)
```

行为：

1. 读取 active Blueprint。
2. `review_enabled=false` 时手动复盘仍可执行，但周期用当前 `review_interval_days`；不自动 due。
3. days = max(1, review_interval_days)。
4. `period_end = today_utc8()`。
5. `period_start = today - (days - 1)`，使 14 天配置严格覆盖 14 个日历日。
6. 若同 profile/blueprint 已存在：
   - `due`
   - `running`
   - `waiting_approval`
   则复用该 open review，不创建重复行。
7. waiting_approval 直接返回原 review，让 UI 显示“审阅 AI 调整”，不得再次启动 AI。

Frontend `startReview()` 只调用这条正式路径。

### Tests

- cadence=7 → snapshot period exactly 7 calendar days。
- cadence=14 → exactly 14。
- cadence=30 → exactly 30。
- running review 连点两次 → 同一个 review id。
- waiting_approval → 不生成第二条 review。

# 3. P0 · PersonalProfile structured facts 必须真的进入 AI Context

## 当前缺口 A

`build_personal_structured()` 产生大量“对象数组”：

```json
{"text":"...","kind":"...","source":"..."}
```

但 `context_builder::flatten_structured()` 对 Array 只读取 string/number，
对象数组会被忽略。

## 当前缺口 B

Dedicated Planner 的 `build_planning_truth_context()` 直接把 `structured_json` 截前 1500 chars，
可能把 `constraints / availability / current_state / unresolved` 截掉，且会形成半截 JSON 文本。

## 修复

1. 修 `flatten_structured()`：
   - Array 中若元素是 object，则递归读取；
   - 至少把 `text / kind / source` 变成可读事实行。
2. 抽一个共享的 `personal_profile_structured_summary()`（或复用 Context Builder helper），
   Dedicated Planner 也用同一个结构化摘要，不再 raw truncate JSON。
3. Planner context 优先级必须确保：
   - availability
   - constraints
   - current_state
   - strengths/weaknesses
   - unresolved
   不因字数截断消失。
4. 可做总字数预算，但必须按字段优先级截断，不允许截断成非法 JSON。

### Tests

构造 structured_json：关键 `availability / constraints` 放在长数据后部，
`build_planning_truth_context()` 和统一 Context Builder 都必须包含关键事实。

# 8. P1 · Planning Source 审查必须结构化给出“为什么改”

## 当前缺口

用户明确要求：上传规划后，AI 若修改必须展示：

```text
原内容
建议内容
修改理由
依据
```

当前 Blueprint schema 没有通用 source review findings，只有 target changes 有 reason/evidence。

## 修复

BlueprintDraft 增加可选：

```json
"source_review": [
  {
    "source_id": 12,
    "source_name": "老师规划.docx",
    "decision": "keep|modify|conflict|missing",
    "original": "原规划内容摘要",
    "suggested": "建议内容",
    "reason": "为什么",
    "evidence": "依据/个人条件/正式目标/可信数据/外部来源"
  }
]
```

规则：

- “生成规划”无 Source 时可空；
- “审查并整理规划”且选择了 Source 时必须有 source_review；
- `modify` 必须 reason 非空；
- 不确定 → conflict/missing，禁止编造。

Compiler：

- source_review 写入 Blueprint content_md + structured_json；
- ChangeSet Review 中用户至少能展开查看这些理由；
- 不把 source_review 自动改成 GoalTarget。
