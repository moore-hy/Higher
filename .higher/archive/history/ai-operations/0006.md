## 14. 错误与修复

### 14.1 Migration 测试断言失败

- 现象：`learning_loop.rs` 与 `learning_hierarchy.rs` 中 `assert_eq!(versions, vec![1, 2])` 失败
- 原因：v003 注册后，setup() 执行 run_migrations 会应用 v001+v002+v003，versions 变成 `[1,2,3]`
- 修复：把两个旧测试文件的断言从 `vec![1, 2]` 改为 `vec![1, 2, 3]`，幂等性 count 从 2 改为 3
- 不视为破坏 DEV-0003/0004：旧测试只是断言 schema 版本号，业务逻辑未变

### 14.2 TaskRepository 缺少 create_with_plan

- 现象：lib.rs 中 `create_task` command 调用 `TaskRepository::create_with_plan` 时编译报错"找不到方法"
- 原因：v003 给 tasks 表加了 plan_id 列，但 TaskRepository 仍只有旧 `create`（不带 plan_id）
- 修复：在 `task.rs` 新增 `create_with_plan(learning_item_id, title, planned_date, plan_id)`，旧 `create` 保留并内部调 `create_with_plan(..., None)`

### 14.3 stage_b_core 测试中 schema_migrations 表缺失

- 现象：`test_migration_upgrade_from_v002_to_v003_preserves_data` 手动执行 v001/v002 up 后，手动插入 schema_migrations 记录时报"表不存在"
- 原因：手动调 `v001_initial::up` / `v002_core_models::up` 跳过了 `ensure_schema_migrations_table`
- 修复：在测试中手动 `CREATE TABLE IF NOT EXISTS schema_migrations (...)` 后再插入版本记录
