# 一、项目概述

## 1.1 项目名称

**Higher**

Higher 是一款面向考研学生的**个人学习规划与执行管理桌面软件**。

它不是简单的 Todo List，也不是普通的学习打卡软件，更不是资料阅读器。

Higher 的核心目标是建立一套完整的：

> **考研目标 → 学科体系 → 知识体系 → 学习计划 → 每日任务 → 学习执行 → 训练反馈 → 薄弱点分析 → 计划调整**

闭环。

最终让用户能够做到：

> **每天打开 Higher，就知道今天应该学什么；学习完成后，系统知道用户学得怎么样；长期积累后，系统能够根据真实学习数据帮助用户调整学习计划。**

---

# 二、项目核心理念

Higher 的核心不是“记录学习”，而是：

> **帮助用户持续、系统、可量化地完成考研准备。**

传统学习软件通常只记录：

* 学习了多久
* 打卡了什么
* 完成了几个任务

Higher 更关注：

* 为什么今天学习这个内容？
* 这个内容属于整个知识体系的什么位置？
* 用户到底掌握了吗？
* 哪些知识点正在成为瓶颈？
* 当前学习时间应该如何分配？
* 下一阶段应该学习什么？

因此 Higher 必须形成完整的学习反馈闭环。

```text
考研目标
    ↓
考试科目
    ↓
知识体系
    ↓
阶段计划
    ↓
周计划
    ↓
每日任务
    ↓
学习执行
    ↓
题目 / 测试
    ↓
学习数据
    ↓
掌握度分析
    ↓
薄弱点发现
    ↓
计划调整
    ↓
下一轮学习
```

# 八、为什么采用 Tauri

Higher 当前只需要适配 Windows 11，但未来可能扩展 Linux。

Tauri 可以：

* 将 Web UI 转换为桌面应用
* 调用系统能力
* 打包 Windows 应用
* 降低运行时资源占用

# 二十五、薄弱点分析

```text

积分

组成原理

长难句
🟠 需要加强
```

薄弱点分析必须逐步从简单规则发展到数据模型。

第一阶段可以采用规则系统。

例如：

```text

→ 薄弱

→ 一般

75% <= 正确率 < 90%
→ 良好

>= 90%
→ 掌握
```

后续再逐步优化。

# 三十八、最终产品愿景

Higher 最终希望成为：

> **一个真正理解“学习过程”的个人考研操作系统。**

它不只是告诉用户：

> “你今天学习了3小时。”

而是能够告诉用户：

> “你为什么没有进步。”

并进一步告诉用户：

> “下一步应该怎么做。”

最终形成：

```text
目标
 ↓
计划
 ↓
行动
 ↓
记录
 ↓
分析
 ↓
反馈
 ↓
调整
 ↓
再次行动
```

形成个人考研学习的长期闭环。

# 四十、项目开发总原则

Higher 的开发必须遵循：

> **先建立系统，再增加功能。**

> **先保证稳定，再追求漂亮。**

> **先解决真正的问题，再加入 AI。**

> **先做一个自己每天愿意使用的软件，再考虑成为大众产品。**

Higher 的第一用户就是项目开发者本人。

因此所有功能设计都应该回答：

> **“这个功能是否真的能帮助一个考研学生更好地学习？”**

如果答案是否定的，则不应该仅仅为了增加功能而加入。

# 四十三、项目最终目标

Higher 不是为了证明技术有多复杂。

它的最终目标只有一个：

> **让一个考研学生能够把漫长、混乱、容易失控的考研过程，变成一个可以被规划、执行、记录、分析和不断优化的系统。**

**Higher = 目标管理 + 知识管理 + 学习计划 + 任务执行 + 训练反馈 + 数据分析 + 智能规划。**

这是 Higher 的核心产品定义。
