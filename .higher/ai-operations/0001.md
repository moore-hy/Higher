   - 移除默认 `tauri_plugin_log` 初始化（其默认日志目录在 AppData，受沙箱限制；本次非必需）。

5. **.gitignore**：忽略 dev 数据库目录。

## 修改理由

- **dev/prod 数据目录分离**：Trae 沙箱禁止访问 `AppData\Local\com.higher.desktop`，导致 Tauri 默认的 webview 数据目录与 plugin_log 日志目录在沙箱内不可写，窗口无法启动。将 dev 模式的 webview 数据目录与 SQLite 数据库放到项目本地（`.webview-data/`、`.data/`），既绕过沙箱限制完成启动验证，又便于开发时重置数据；prod 模式仍用系统 AppData，行为符合桌面应用规范。这是合理的 dev/prod 环境隔离，非为验证而 hack。
- **手动创建窗口替代 config 配置**：Tauri config 的 `dataDirectory` 是相对 `appDataDir` 的路径（仍在 AppData 下），无法设绝对路径；只有 Rust API `WebviewWindowBuilder::data_directory` 可设绝对路径，因此改为代码建窗。
- **移除 plugin_log**：其默认日志目录在 AppData，受沙箱限制；本次为地基初始化，日志非必需，移除以解除启动阻塞。后续可重新引入并配置日志目录到本地。
- **rusqlite（bundled）而非 tauri-plugin-sql**：在 Rust 端管理数据库，符合"UI 不直接操作 SQLite、通过 Repository 分层"的架构原则；bundled 自带 SQLite 源码，无需系统安装 SQLite，降低部署依赖。
