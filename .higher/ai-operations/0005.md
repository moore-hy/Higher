### 4.3 第二部分：七大核心系统（新增）

正式定义 Higher 的七个核心系统，形成完整学习闭环：

```
1. Goal System（目标系统）      —— 为什么学？最终要达到什么？
2. Knowledge System（知识系统）  —— 到底要学什么？
3. Planning System（计划系统）   —— 什么时候学？按什么顺序学？
4. Execution System（执行系统）  —— 实际学了什么？
5. Evaluation System（评估系统） —— 我到底有没有学会？
6. Feedback System（反馈系统）   —— 哪里出了问题？
7. Adjustment System（调整系统） —— 下一步怎么改？
```

完整学习闭环：

```
Goal System
     ↓
Knowledge System
     ↓
Planning System
     ↓
Execution System
     ↓
Evaluation System
     ↓
Feedback System
     ↓
Adjustment System
     │
     └──────────→ 回到新的 Planning / Execution
```

明确：这些系统不是七个完全孤立的页面，而是**一套相互连接的学习运行机制**。

### 4.4 第三部分：核心系统成熟度（新增）

#### 成熟度等级定义

| 等级 | 含义 |

| L0 | 未开始 |
| L1 | 最小骨架 |
| L2 | 基础可用 |

#### 当前系统成熟度表（基于真实代码）

| 核心系统 | 成熟度 | 当前能力 | 下一关键缺口 |
|---|---:|---|---|
| Goal System | **L1** | 创建 Goal、查看 Goal 列表（DEV-0003） | 编辑 / 归档 / 目标时间范围 |
| Knowledge System | **L1** | Learning Item Tree V1：创建根/子项、按 Goal 隔离、树形 UI、修改 mastery_status、跨 Goal parent 防护（DEV-0003/0004） | 节点重命名 / 删除 / 移动 / 知识结构完善 |
| Planning System | **L0** | 未开始（Task.planned_date 仅作为 Execution 的计划日期提示，不构成独立 Planning 模型） | 阶段 / 计划数据模型 |
| Execution System | **L2** | Task + Study Session + History + 自动 duration 计算 + 持久化 + 1 Task 多 Session + 结束不自动完成 Task（DEV-0003） | Session 异常恢复 / 多设备 / 完整执行统计 |
| Evaluation System | **L0** | 未开始 | 通用测试 / 验证数据模型 |
| Feedback System | **L0** | 当前仅有 mastery_status / Note，但它们属于 Knowledge/Execution 的内嵌字段，不构成独立 Feedback 模型 | 问题与反馈数据模型 |
| Adjustment System | **L0** | 未开始 | 调整机制 |

> 上述等级严格基于当前真实代码判断，未虚高。
