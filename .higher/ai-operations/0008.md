## 6. 旧产品结构存在的问题（来自 TASK + 文档诊断过程汇总）

1. **产品定义在文档中不占位置**：旧 PROJECT.md 前 100 行里是版本号、文件列表、成熟度表，一个新来的人不知道 Higher 是给谁用的
2. **Stage C 的顺序不对**：Evaluation 刚落地就进入 Feedback / Adjustment，等于跳过了"把现有能力组织成真正用户体验"这一步
3. **UI 与 DB 实体一一对应**：当前页面数量 = DB 表数量，这种后台管理式 UI 维护成本极高且不符合学习流程
4. **PROJECT 承担了操作日志职责**：DEV-0006 加了多少 command、DEV-0007 新增几个函数——这类信息应该在 ai-operations/，不是 PROJECT.md
5. **"核心学习循环"没有 UX 视图**：只有 Goal→Knowledge→Planning→Execution→Evaluation 这种开发者视角，没有"用户今天打开 Higher 之后的路径"
6. **没有产品保护规则**：任何新功能都能加进来，容易膨胀成 Todo 工具 + 计时器 + 题库组合大杂烩
7. **功能是否值得做没有判据**：没有"这功能是否帮我看清知识？看清进度？发现问题？明确下一步？理解成长？"的检查清单
