## Migration 设计

### schema 版本记录

新建 `schema_migrations` 表：

```sql
CREATE TABLE IF NOT EXISTS schema_migrations (
    version     INTEGER PRIMARY KEY NOT NULL,
    name        TEXT NOT NULL,
    executed_at TEXT NOT NULL DEFAULT (datetime('now'))
);
```

可靠判断：version 为主键，已执行的 version 存于此表；未在此表的即未执行；按 version 升序遍历保证执行顺序。

### 模块结构

```
src-tauri/src/migrations/
├── mod.rs              Migration 注册与执行引擎
└── v001_initial.rs     第 1 个 Migration（settings 表）
```

- `Migration` 结构体：`{ version, name, up: fn(&Connection) -> Result }`
- `MIGRATIONS: &[Migration]`：按 version 升序的静态数组，新增 Migration 在此追加
- `latest_version()`：返回最新注册版本（供 db_status）
- `run_migrations(&Connection)`：核心执行函数

### 执行流程

```
run_migrations(conn):
  1. ensure_schema_migrations_table（IF NOT EXISTS 建 schema_migrations）
  2. executed_versions（SELECT version 集合）
  3. for m in MIGRATIONS（升序）:
       if done.contains(m.version) → 跳过
       else:
         tx = conn.unchecked_transaction()
         (m.up)(&tx)            // 在事务内执行
         tx.execute(INSERT schema_migrations ...)
         tx.commit()            // 提交后才记录为成功
  4. 打印日志（applied / already up to date）
```

### 事务保证

每个 Migration 在独立事务（`unchecked_transaction`）内执行。`up` 与 `INSERT schema_migrations` 在同一事务：up 失败则事务回滚，不写入记录，函数返回 Err，**不会记录为成功**。

### 幂等与安全

- 重复启动：executed_versions 命中已执行 version，跳过，不重复创建。
- 已执行不会报破坏性错误，仅打印 "already up to date"。

### 已存在数据库兼容

当前 dev 数据库 `src-tauri/.data/higher.db` 由 DEV-0001 创建，已有 `settings` 表但无 `schema_migrations`。v001 使用 `CREATE TABLE IF NOT EXISTS settings`：

- 全新数据库：创建 settings 表
- DEV-0001 遗留库：settings 已存在则跳过创建，不报错、不删数据

首次 run_migrations 会建 schema_migrations、执行 v001（IF NOT EXISTS 安全通过）、写入 version=1。**未删除 higher.db，未破坏现有数据。**

### 新增 Migration 的方式（未来）

1. 新建 `migrations/v0xx_name.rs`，实现 `pub fn up(conn: &Connection) -> rusqlite::Result<()>`
2. 在 `mod.rs` 声明 `pub mod v0xx_name;`
3. 在 `MIGRATIONS` 数组按 version 升序追加条目
4. 不得修改或删除已发布 Migration
